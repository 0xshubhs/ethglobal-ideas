### 1.3 Judgement: what these judges will reward

1. **The AI call is the product, not an accessory.** If a judge can imagine the app with the model removed, it loses. Each idea below states the removal sentence and passes the "would anyone notice" test.
2. **Evidence on screen.** `request_id`, provider, trust tier and cost under every AI output, and the same IDs in the README. 0G said teams under-report; over-report instead.
3. **A refusal you can trigger.** 503 on the private tier, a safe-stop, a refused job, a co-signature withheld. The verifier pattern beat memory layers at Open Agents.
4. **Several 0G layers.** Compute plus Storage plus Chain where it is natural (Physical AI requires all three in practice).
5. **Auditor-grade repos.** Foundry tests and invariant fuzzing on every contract, and a "what is real, what is mocked" section. This is the team's cheapest edge.

### 1.4 Judgement: the obvious entries we assume several teams will submit

- Build with 0G PC: an AI image or video "wrapped" generator, an AI tutor or quiz, a transaction explainer, an AI wallet guard, a "Spotify Wrapped" for wallets.
- Physical AI: zerobot's mock Go2 driven by a prompt ("walk forward, sit"), with logs uploaded to 0G Storage. A chatbot with a robot body will be common despite the "Not wanted" line.
- Agents That Pay: a comfy token launch plus a chatbot, or an x402 pay-per-call wrapper whose revenue comes from the team's own test wallet.

Every final idea below has to beat these on at least one property a judge can check.

### 4.2 Rank 1. Drill: a daily scam call you have to beat

- **Pitch:** every day at 05:30 IST (00:00 UTC, when iAI credits refresh) a new three-minute voice call from a "support agent", "police officer" or "airdrop team", rebuilt from a real incident. The scammer is a sealed model that adapts to what you say. You win by refusing in time.
- **Falsifiable promise:** "Every scammer line and every grade is a `private`-tier model call with a request ID on screen; if no sealed provider answers, the drill stops instead of falling back to an unsealed model."
- **Demo moment:** a judge taps "Today's call". The scammer (text plus standard-tier voice, labelled) asks the judge to "verify" by signing a message. The app shows the request as a mock wallet popup rendered from real calldata (`setApprovalForAll` to an unknown operator). The judge says "no, that hands over all my NFTs". The sealed grader returns "Refused at turn 3, reason correct" with request IDs. A teammate replays the same call and says "okay, signing": the grade explains which line should have stopped them, citing the real incident's tx hash.
- **How the AI stays central (C3):** the scammer's replies are generated live from your words (`whisper-large-v3` sealed transcription, `glm-5.3` sealed role-play constrained to the incident card), and `vela-2.0-9b` scores "did the user refuse before the harmful step" with a probability. Removal sentence: "Without 0G there is no one on the other end of the call: no adaptive scammer, no spoken grading, only a static quiz." Wallet popups are deterministic renders of real calldata, so no text is hallucinated on screen.
- **Second tab (absorbed from Hang Up):** "Check a real one": forward a suspicious voice note; the same sealed pipeline marks the phrases that match drill patterns. This uses the same stack and gives a real-world reason to keep the app installed.
- **Requirement checklist:**
  - C1 inference in the main flow with request IDs: met (every turn).
  - C2 judge can try, reason to return: met (daily call, streak, the call changes each day). Live link required.
  - C3 removal sentence and not a chat wrapper: met; the user never types to a chatbot, and removing the model removes the call.
  - C4 iAI bonus: fits naturally (daily drill spends daily credits), but the sign-in path is undocumented ([iAI docs](https://iai.finance/docs)); build without it and add it only if the workshop shows a path.
  - Not wanted: clear on both items.
  - Submission: repo, video under 3 min, live link, Telegram and X. Contracts: none required; optional streak contract.
- **Why it beats rivals:** the obvious rival is an AI security quiz. Drill is adversarial, voice-first and changes every day, and it uses three of 0G's sealed models in one flow. "Spend today's expiring credits on today's drill" is a sentence 0G's iAI team can repeat.
- **Closest prior winners:** none among 0G winners handles voice. Solidity Cell (Cannes 2025, no prize) was a developer escape room. 0run (Lisbon 1st) is the consumer-habit precedent.
- **Stack:** Next.js PWA, a small Node server that holds the `sk-` key and proxies the Router with `X-0G-Provider-Trust-Mode: private`, incident cards written by the team (WazirX signer phishing, CoinDCX dead-wallet deposits, address poisoning, 7702 sweeper delegations; `00_season.md`), browser MediaRecorder for audio.
- **Difficulty (36 h):** medium. Latency of a transcription plus generation round trip is the main risk; keep turns short and stream the text.
- **Scores:** C1 9, C2 9, C3 9, C4 7, N 7, F 7. Overall **7.9**.
- **Judge notes:** 0G judge: "This is the consumer app we asked for; I want to see the private tier refuse once on camera." Veteran: "Write ten incident cards before Thursday as research notes, but the code and prompts must be written after 21:00. Script the 4 minute finalist demo around one call that the judge loses."

### 4.3 Rank 2. Daily Bug: yesterday's exploit as today's five-minute audit

- **Pitch:** one small contract a day, carrying the root cause of a real recent exploit, rewritten by a sealed model so it cannot be searched. You find the bug in five minutes and explain it; the model grades your finding.
- **Falsifiable promise:** "No puzzle is published unless the team's reference exploit breaks it in Foundry and the fixed version passes; a generated contract that the exploit cannot break is thrown away, and the log shows how many were rejected."
- **Demo moment:** the judge opens today's puzzle (a donation-attack variant, after Tectonic, 30 Aug 2026, in `00_season.md`). They type "the share price can be inflated by a direct transfer before the first deposit". The grade returns "correct root cause, missed the rounding direction", with the request ID. The panel then shows the verifier log: three generated variants, two failed the reference exploit and were discarded, one passed.
- **How the AI stays central:** `glm-5.3` (sealed) mutates the vulnerability template into a fresh contract and grades free-text findings against a hidden rubric. Removal sentence: "Without 0G there is no new puzzle tomorrow and no one to grade a finding written in your own words." The deterministic Foundry check is the verifier that keeps the model honest (the winning pattern from Open Agents).
- **Requirement checklist:**
  - C1: met for grading (per user, per submission, request ID shown). Generation is a daily batch; show its request IDs on the puzzle page as well.
  - C2: met (daily puzzle, streak, leaderboard). Audience is developers and audit learners. **Risk:** whether 0G counts developers as "consumers"; workshop question 8.
  - C3: met.
  - C4: fits (daily grading spends daily credits); path undocumented.
  - Not wanted: clear.
  - Submission: standard; contracts "(if any)": none required.
- **Why it beats rivals:** Ethernaut and Damn Vulnerable DeFi are static and searchable. Daily Bug is new every day, tied to the news, and every puzzle is proven exploitable before release. No rival team will have a working verifier gate.
- **Closest prior winners:** CodeGuardian iNFT (Open Agents, negative control), AgentMeshx (audit agents). Neither is a consumer habit product.
- **Stack:** Next.js, Node server with the Router key, a Foundry runner in a container with no network access (forge test against the generated contract and the team's exploit), template library written during the event.
- **Difficulty (36 h):** medium. Generated Solidity that compiles and keeps exactly one bug is the risk; constrain the model to edit inside marked regions of a template.
- **Scores:** C1 8, C2 8, C3 9, C4 7, N 7, F 6. Overall **7.4**.
- **Judge notes:** 0G judge: "The verifier gate is the reason this places; show the rejected variants." Veteran: "Sandbox the forge runner properly; a judge will try to paste a contract that calls `vm.ffi`."

### 4.4 Rank 3. Rug Odds: you against a sealed model, scored by tomorrow's chain

- **Pitch:** each morning, five tokens launched in the last 24 hours. You and a sealed decision model each give a probability that liquidity is pulled within 72 hours. The chain settles who was right.
- **Falsifiable promise:** "The model's probability is committed on-chain, with its request ID, before you answer; the score uses only on-chain events after the commit, and the model's public Brier score includes every call, including its misses."
- **Demo moment:** the judge sees a card (fee recipients, creator wallet history, LP lock status) and the model's sealed "rug in 72 h: 0.81" behind a commit hash. The judge says 0.4. The reveal shows yesterday's resolved cards: the model was right on four, wrong on one, and the wrong one is shown first.
- **How the AI stays central:** `laya` or `vela-2.0-9b` (TeeML, calibrated probabilities via `POST /decisions`) is the opponent and the odds-setter; `glm-5.3` writes the case card. Removal sentence: "Without 0G there is no opponent to beat and no calibrated odds to learn from; you would only have raw token data."
- **Requirement checklist:**
  - C1: met (the model's call is the first thing on every card).
  - C2: strongest of the five: results arrive tomorrow, which is literally a reason to come back.
  - C3: met, though a judge may argue the game survives without the opponent; the README must lead with the model's public track record.
  - C4: fits (daily calls).
  - Not wanted: clear. **Risk (Judgement):** memecoin launchpads are out of season (`00_season.md` section 4); frame it as rug literacy, not trading, and do not link to any buy button.
  - Submission: commit contract on 0G Galileo; addresses in README.
- **Why it beats rivals:** prediction games are common, but none puts 0G's own decision model on a public, falsifiable scoreboard. 0G gets a live calibration report for `laya`.
- **Closest prior winners:** KOLlateral (Lisbon 3rd: calls priced against history, a public record), Whale.fun (New Delhi 1st, launch safety).
- **Stack:** Next.js, an indexer over one chain's new-token events (Base or 0G mainnet comfy launches), commit-reveal contract on Galileo (Foundry tests and fuzzing), Router decisions endpoint.
- **Difficulty (36 h):** medium. Only about 36 hours of resolutions will exist at demo time, so seed the scoreboard with launches from the days before the event, resolved from historical chain data (data, not project code).
- **Scores:** C1 8, C2 9, C3 7, C4 7, N 6, F 7. Overall **7.3**.
- **Judge notes:** 0G judge: "Publishing our model's misses is brave and we would like it." Veteran: "Make sure the commit happens before the user answers, or a judge will call it theatre."

### 4.5 Rank 4. Delegate Desk: does the calldata do what the proposal says

- **Pitch:** for delegates who vote in many DAOs, a morning queue of new proposals where a sealed model checks the prose against the decoded calldata and flags any effect the text does not mention.
- **Falsifiable promise:** "If a proposal's calldata calls a contract or function its text does not mention, the card is red before voting opens and names the exact call."
- **Demo moment:** on a fork, the team submits a proposal whose text says "update fee recipient" while call 2 of 3 is `transferOwnership`. The card turns red with the request ID; a clean proposal stays green.
- **How the AI stays central:** deterministic decoding produces the call list; the model judges whether the prose covers each call (natural language against effects, which code alone cannot do). Removal sentence: "Without 0G you get raw calldata and a forum post and must compare them yourself."
- **Requirement checklist:** C1 met; C2 moderate (delegates see new proposals most days across many DAOs; ordinary holders do not); C3 met; C4 weak (per proposal, not per user, unless each delegate's own notes are graded); Not wanted clear; contracts: fork governor only, none required.
- **Why it beats rivals:** AI proposal summarizers are common. The text-versus-calldata mismatch is a check, not a summary, and it names the call.
- **Closest prior winners:** Don't Get Drained (intent against transaction, Cannes 2026 DeFi 3rd). No 0G winner has looked at governance.
- **Stack:** Next.js, governor indexer (Governor Bravo and OZ Governor events), calldata decoder, Router; optional Chainlink "Best workflow with CRE" watching governors and calling the verdict endpoint (CRE needs "Integrate at least one blockchain with an external API, system, data source, LLM, or AI agent" and a CLI simulation, `00_current_tracks.md`).
- **Difficulty (36 h):** medium.
- **Scores:** C1 8, C2 6, C3 8, C4 5, N 6, F 6. Overall **6.5**.
- **Judge notes:** 0G judge: "Good mechanism, thin consumer story." Veteran: "Find one real past governance attack where text and code differed and cite it in the README; that is the whole pitch."

### 4.6 Rank 5. Upgrade Watch: your approvals, re-read on every upgrade

- **Pitch:** when a proxy you approved is upgraded, a sealed model reads the implementation diff once and publishes a verdict; your device matches it against your approvals without telling anyone what you approved.
- **Falsifiable promise:** "Within one block of an `Upgraded` event on a watched proxy, a verdict naming the changed functions is published with its request ID, and any function the model names that the new bytecode lacks is flagged as a model error."
- **Demo moment:** a judge approves demo USDC to a vault proxy on a fork; a teammate upgrades it to an implementation that adds `sweep(address)`. Workshop: Thu 5 Nov 15:30 to 15:50 IST, Workshop Room 1, "One API, All of AI: Building on 0G Private Computer" (Gathin T, DevRel). It clashes with Hedera in Room 2. ([event page](https://ethglobal.com/events/mumbai)) Most decisive first:

1. **Two 0G tracks, one project:** can one project win both Physical AI and Agents That Pay (or place in two 0G tracks)? This decides whether Robot That Pays is the main build.
2. **What counts as money for Agents That Pay:** does a testnet Router balance funded through the testnet Payment Layer count as "money in", or must the loop run on mainnet? Do payments from judges and other hackers count as outside revenue? Can the credits 0G gives teams be the seed balance, or does that read as "a human refills"?
3. **iAI bonus path:** how does a third-party app let a user "sign in with their 0G account" and spend their own daily credits, given that the Router docs list only `sk-` and `mk-` keys and the iAI docs mention only "0G Private Computer, 0G App, and other supported apps"? Is there a delegated key or OAuth flow this week, and can users in India use iAI ("not available in some jurisdictions")?
4. **Request ID evidence:** is `x_0g_trace.request_id` from the Router what judges check, or the broker's `ZG-Res-Key`? Is there a public endpoint where a third party can look up which model, provider and trust tier served a request ID, and fetch its TEE signature? (This decides Hire Board and how every README shows proof.)
5. **Physical AI scope:** does a desktop companion with no motion (Witness) count as an "agent with a body" in the Personal devices lane? What qualifies as "real hardware" (a Raspberry Pi device, not a robot)? Will the booth have a Unitree Go2 running zerobot? Do `laya` and `vela-2.0-9b` count as the "decision model"? Is a safe-stop that refuses and asks a human treated as "faking the decision"?
6. **Contracts:** must Physical AI and Agents That Pay contract addresses be on 0G Chain (Galileo or mainnet), or are other chains acceptable for parts of the system (for example ENSv2 on Sepolia)?
7. **Credits and limits:** how many compute credits does each team get, on mainnet or testnet Router, and do image, video and voice models draw from the same budget? Is there a per-key spend limit we can set (the Authentication page does not mention one), and what are the Galileo faucet limits at faucet.0g.ai?
8. **Who is a consumer:** does a daily app for developers or audit learners (Daily Bug) or for DAO delegates (Delegate Desk) count as "a consumer app", and is "a reason someone comes back tomorrow" judged by mechanism or by evidence of real returning users?
9. **Central or cosmetic:** does a model call made once per event and shared across users (one verdict per upgrade, one puzzle per day) count as "in your main user flow", or must each user's action trigger its own call?
10. **Trust tiers:** do judges weigh sealed (`private`, TeeML) calls above `verified` (TeeTLS) ones? Would they accept standard-tier TTS in a flow whose other calls are sealed, if the README labels it?
11. **SDK versions:** which versions should we pin: `@0gfoundation/0g-ts-sdk` (versus the old `@0glabs` name), the storage SDK for Node servers (past teams hit `XMLHttpRequest` errors), zerobot's current release and its supported testnet, and comfy-cli 0.9.4?
12. **comfy:** how do judges treat attendees buying the agent's token during the demo, and is a risk feed on comfy launches welcome?
13. **Judging format:** will 0G combine booth demos with repo review as at Lisbon? Is a booth demo required for the real-hardware place, and what is the quality threshold behind the discretion clause on Physical AI?
